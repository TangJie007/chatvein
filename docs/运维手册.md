## 配置总表（环境变量）

本文件是 **唯一全量表**：想知道某个 `CHATVEIN_*` 干什么、默认值是多少，只看这里。
代码里新增开关必须同步本表（`backend/tests/test_config.py` 会用 AST 扫一遍代码，
漏写就测试失败）。

### 0. 口径

- **布尔开关**：没设 → 用默认值；显式设了 → `""` / `0` / `false` / `no` / `off` 算关，
  其余算开。统一读 `backend/agents/config.py::flag`，别再各写一套 `== "1"`。
- **数字开关**：写错直接抛 `ValueError`（启动即失败），不静默退回默认值——
  否则「为什么设了没生效」要查一天。读 `config.number`。
- **生效时机**：启动时读取。开发期 `CHATVEIN_RELOAD=1` 会重载 Python 代码，
  但环境变量本身要重启进程才变。
- Tauri 打包版由外壳（`src-tauri/src/backend.rs`）注入 `CHATVEIN_TOKEN` / 端口 / 数据目录，
  **不要**在设置文件里手写这些，会覆盖掉真实值。

## 离线评测

评测的目标只有一个：**改 prompt / 改工具 / 改路由之后，能知道质量有没有掉**。它不覆盖 UI，也不测性能，跑完给一份 JSON 报告。

### 用法

```powershell
# 默认跑 backend/eval/cases/smoke.json
.\tools\run_eval.ps1

# 只校验用例文件（不进模型，可进 pre-commit）
.\tools\run_eval.ps1 -Rest @("--dry-run")

# 加 LLM 评分（默认关），指定评分模型
.\tools\run_eval.ps1 -Judge -Rest @("--judge-model", "<models.id>")

# 直接调脚本
.\.venv\Scripts\python.exe backend\eval\runner.py --cases backend\eval\cases\smoke.json --report eval-report.json
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--cases` | 用例文件，默认 `backend/eval/cases/smoke.json` |
| `--role` | 角色 id；缺省用主对话角色 |
| `--limit` | 只跑前 N 条（调试用） |
| `--judge` | 启用 LLM 评分（默认关闭） |
| `--judge-model` | 评分模型配置 id；缺省复用被测角色自己的模型（同模型评分有偏，趋势仍可比） |
| `--judge-threshold` | 达标线，默认 3.5（四维均值 0-5） |
| `--report` | 报告路径，`-` 表示打到 stdout |
| `--max-seconds` | 整批时间预算，超出的用例记为 skipped |
| `--dry-run` | 只校验用例文件 |
| `--quiet` | 只打印汇总，不逐条 |

退出码：`0` 全通过；`1` 有 fail / error / 跳过；`2` 用例文件或模型配置有问题。

### 用例格式

```json
{
  "suite": "smoke",
  "cases": [
    {
      "id": "arithmetic",
      "message": "算一下 37 * 19 + 128 等于多少。",
      "expect_tools": ["calculator"],
      "forbid_tools": ["get_current_time"],
      "expect_substring": ["831"],
      "forbid_substring": ["无法计算"],
      "rubric": "结果必须是 831；只用计算工具。"
    }
  ]
}
```

- `expect_tools` 里的**每一个**都必须被调用过；`forbid_tools` 一个都不能出现。
- `expect_substring` / `forbid_substring` 对最终回复做字面判断（大小写敏感），适合钉住关键事实（数字、专有名词、接口名）。
- `rubric` 只给 LLM 评分看，规则断言不读它。
- 列表字段写成字符串等价于单元素数组，手写用例少一层括号。
- 顶层也可以是裸数组（suite 取文件名）。

### 判定

1. **规则断言（必跑）**：`reply_non_empty` 永远检查；其余按用例字段。任何一条不满足 → `fail`。
2. **LLM 评分（可选）**：`relevance / correctness / tool_use / format` 各 0-5，取均值；低于阈值 → `fail`。
3. 跑用例本身抛异常（没配模型、工具崩）→ `error`，不会带走整批。

为什么要分离：规则断言是硬门槛，模型抖一下也不该让整套评测失去意义；judge 看的是「答得好不好」，只用于趋势。

### 运行环境

- 每条用例：`create_conversation_dir()` → `use_conversation_sandbox()` → `bind_turn()`，跑完删除目录。工具产生的文件不会进用户工作区，也不会因为「没有沙箱」直接失败。
- 直接调用 `pipeline.run_pipeline`，不起 HTTP 服务、不发 SSE——CI 上能跑，也不需要前端。
- 不写 `turn_traces`（不污染真实会话的追踪与指标）；需要看单轮轨迹时用 `--report -` 里的 `judge` / `checks` 字段。

### 报告字段

```json
{
  "schema_version": 1,
  "suite": "smoke",
  "generated_at": "2026-11-20T03:20:00+00:00",
  "role": {"id": "...", "name": "...", "model_id": "..."},
  "judge": {"enabled": false, "model_id": null, "threshold": 3.5},
  "totals": {"cases": 4, "executed": 4, "passed": 3, "failed": 1, "errors": 0, "skipped": 0, "pass_rate": 0.75, "elapsed_ms": 5120},
  "judge_mean": null,
  "results": [
    {"id": "arithmetic", "status": "pass", "elapsed_ms": 900, "difficulty": "simple",
     "reply": "831", "tools": [{"name": "calculator", "status": "ok"}],
     "checks": [{"name": "expect_tools", "ok": true, "detail": ""}], "judge": null, "error": null}
  ]
}
```

`results[].status` 取 `pass` / `fail` / `error`。`reply` 超过 4000 字会截断（报告不是日志，别塞整篇长文）。

### 与指标、OTel 的关系

- **指标**（`GET /api/conversations/{id}/metrics`）来自真实使用产生的追踪，eval 报告来自离线用例；两者互补，不要互相替代。
- **OTel**（`CHATVEIN_OTEL=1`）只导出真实对话的轮次，不导出 eval 运行（eval 不起 `tracing` 落库，导出没有意义）。

### 局限（当前已知）

- 用例不能预置本地文件，测不了「读某个文件」类工具；需要时再引入 `${case_dir}` 约定。
- 没有 prompt 版本号：报告只带 role / model。等 prompt registry 落地后再补，避免先造一个假字段。
- 单条用例不做硬超时（无法安全杀线程），用 `--max-seconds` 控整批预算。
- 没有 CI workflow：仓库当前无 workflow 文件，接 CI 只需执行 `tools/run_eval.ps1` 并读退出码。

## 工具测试用例（人工评测）

> 本文合并原先 `docs/test/` 下 11 篇分域用例与说明；按「先通用验收、再分域用例」组织。

在 ChatVein 里用**自然语言**测「Agent 会不会正确选型并调用工具」。  
不是 `pytest`，而是对着 UI / Trace 验收。

### 怎么测

1. 新开一个会话（干净 `output/` / `runs/`）。
2. 把用例里的「用户输入」原样发给 Agent。
3. 打开 Trace / 工具轨迹，对照「期望工具」与「验收」。
4. 在下表勾选通过与否。

| 状态 | 含义 |
| --- | --- |
| ✅ | 选型正确、参数合理、结果可用 |
| ⚠️ | 能完成任务但绕路/多轮空转 |
| ❌ | 未调到工具 / 路径错 / 会话根丢失 / 胡编结果 |

### 用例分组

| 小节 | 分组 |
| --- | --- |
| 01 · 文件系统（mcp-fs） | `mcp-fs` 文件系统 |
| 02 · Core（时间 / 计算 / 本机） | `core` 时间 / 计算 / 本机 |
| 03 · 联网（mcp-web） | `mcp-web` 搜索与抓取 |
| 04 · SQLite 只读（mcp-sqlite） | `mcp-sqlite` 只读库 |
| 05 · 知识库（mcp-kb + 管理 UI） | `mcp-kb` 知识库 |
| 06 · 代码沙箱（mcp-codesandbox） | `mcp-codesandbox` 代码沙箱 |
| 07 · Shell（Bash / PowerShell） | Bash / PowerShell |
| 08 · IP 归属地（mcp-ip） | `mcp-ip` 归属地 |
| 09 · OCR（mcp-ocr） | `mcp-ocr` 识字 |
| 10 · 浏览器（mcp-browser） | `mcp-browser`（需本机浏览器） |
| 11 · 组合与回归坑 | 多工具组合 / 回归坑 |

### 通用验收要点

- **会话内路径**：产物应在 `output/`（相对路径如 `output/xxx.txt` 即可）；不要写到主空间根。
- **扩展名**：用户说了 `.txt` / `.md` 等，文件名必须带上。
- **会话外路径**：须绝对路径 + 确认弹窗；相对 `../` 应被拒绝。
- **会话 ContextVar**：ReAct 超时线程须继承沙箱（否则会报「当前没有会话工作区」）。
- **停手**：结果够了应作答，不要同参空转。

工作区权威说明见 [`机制详解.md`](./机制详解.md) §工作区模型；工具矩阵见 [`Agent与功能.md`](./Agent与功能.md) §Agent流水线 12。

| 崩溃自愈 | 监督线程 `try_wait` 轮询，异常退出自动重启（最多 3 次），重启成功后重新广播 `backend-ready`，前端自动恢复 |

| SSRF 防护 | `web_fetch` 拒绝内网/回环/链路本地/云元数据地址；httpx 逐跳重定向校验 |
| 注入缓解 | 网页正文、搜索结果、第三方 SKILL.md 以 `<untrusted>` 定界符隔离并声明「非指令」 |
| 前端韧性 | 顶层 ErrorBoundary 防白屏；请求默认 30s 超时；GET 自动重试 1 次；后端掉线自动重连 |

#### 2. 代码签名与公证（缺一不可）
- **Windows Authenticode 签名**：购买/使用代码签名证书（EV/OV），用 `signtool.exe` 或 CI 的 `azure/sign-action` 签名：
  - `backend.exe` 与 `ChatVein.exe` 都要签；建议同时签 `_internal` 里的关键 dll（至少 exe）。
  - 不签名的后果：SmartScreen「未知发布者」红色拦截。
- **macOS 公证（Notarization）**：需 Apple Developer 账号 + Developer ID 证书，`codesign --deep --force --options runtime` 后 `notarytool submit` 公证并 stapler。否则 Gatekeeper 报「已损坏，无法打开」。

#### 3. 自动更新（Updater）— 已走 COS 模式
Tauri v2 updater 是「静态 HTTP 端点」模型，更新走腾讯云 COS 对象存储。当前骨架已代码化：
- `src-tauri/tauri.conf.json` → `plugins.updater`：已内嵌公钥（`C:\Users\Administrator\.tauri\chatvein.key.pub`）与真实 COS endpoint `https://lingjin-app-1254228834.cos.ap-guangzhou.myqcloud.com/chatvein/updater/latest.json`。
- Rust 已注册 `tauri-plugin-updater` + `tauri-plugin-process`；前端设置页「软件更新」卡片 + 启动时按 `autoUpdate` 偏好自动检查（发现新版系统弹窗询问，不静默安装）。endpoint 无效时前端静默跳过 / 设置页提示（历史教训：曾用 `<bucket>/<region>` 占位符导致插件启动 panic）。
- 发版脚本 `tools/release_updater.ps1`：build → sign → 生成 `latest.json` + `.sig` → 提示上传。

**密钥对**（已生成一次，私钥勿外传）：
```powershell
# 私钥：C:\Users\Administrator\.tauri\chatvein.key（生产发布前建议重新生成并妥善保管）
# 公钥：C:\Users\Administrator\.tauri\chatvein.key.pub（已内嵌进 tauri.conf.json）
```

**每次发版流程**（真实 endpoint 已内置在 `tauri.conf.json`，直接构建即可）：
```powershell
npm run tauri build
.\tools\release_updater.ps1 -Version 0.1.1 -Notes "本次更新说明"
# 把 dist-updater/ 下文件上传到 COS 桶 chatvein/updater/（公有读或 CDN 可读）
# 上传后在 COS 控制台 / CDN 刷新 latest.json 缓存
```
> 如需临时指向其他环境（如测试桶），可用 `tauri build --config` 覆盖 endpoints：`npm run tauri build -- --config "{`"plugins`":{`"updater`":{`"endpoints`":[`"https://...`"]}}}"`。

**COS 桶结构**：
```
chatvein/updater/
  latest.json                      ← 更新清单（含版本/签名/URL）
  ChatVein_0.1.1_x64-setup.exe     ← NSIS 安装包（updater 仅支持 NSIS，不支持 MSI）
```

**注意点**：
- 安装包必须是 **NSIS（.exe）**，updater 不支持 MSI；`bundle.targets` 为 `"all"` 会同时出 nsis，确认 `target/release/bundle/nsis/` 存在。
- COS 桶建议**私有写 + 公有读**（只放更新产物）；签名校验保证包完整性，篡改会被拒绝。
- **中国大陆访问 COS 自带域名需 ICP 备案**；未备案就接 CDN（回源 COS）或改用海外 region 桶。
- 每次发布后必须刷新 CDN 缓存，否则客户端拿到旧清单。
- 没有更新通道时，线上问题只能靠用户手动重装——务必在首批内测前完成。

#### 4. 跨平台产物
- 当前 `tools/build_backend.ps1` 仅面向 Windows。macOS / Linux 需：
  - `backend/backend.spec` 对应产物名与路径的适配；
  - Tauri `bundle.targets` 与签名/公证流程；
  - Linux 的 `AppImage`/`deb` + `libwebkit2gtk` 依赖说明。
- 若暂无跨平台计划，至少在 README 声明「当前仅支持 Windows x64」。
