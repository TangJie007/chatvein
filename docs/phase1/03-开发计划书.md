## 1 里程碑总览

对齐总 PRD 第 9 节，本期落在 M0–M2，初赛 M3 为演练调优期。

| 里程碑 | 时间 | 目标 | 出口标准（Definition of Done） |
|--------|------|------|-------------------------------|
| **M0 基线与脚手架** | 9/3–9/6 | 报名 + 实测基线 + 搭好 `@chatvein/*` 空包骨架 | `baseline.json` 落盘；10 个能力包可 build/test；CLI 空命令可跑 |

## 2 包建设顺序（依赖驱动）

```
common  →  models ┐
                  ├→ tools ┐
                  │        ├→ sandbox ┐
                  │        │          ├→ verifier ┐
                  └→ context ┘        │            ├→ orchestrator ┐
                  compiler ───────────┘            │               ├→ core → service
                  observability（横切，最早搭总线） ┘               ┘            │
                                                                                 └→ app（GUI）
```

施工顺序：`common` → `observability(事件总线+落盘)` → `models` → `tools`+`context` → `sandbox` → `verifier` → `compiler` → `orchestrator` → `core` → `service(CLI)` → 端到端打通 → `service(sidecar)` → `app(GUI)`。

## 4 关键路径与缓冲

- **关键路径**：common → models/tools → orchestrator → core → service(CLI) 端到端（M1）→ sidecar + app（M2）。
- **缓冲策略**：M1 的 app GUI（M1-10）若紧张，可先用 CLI 验证逻辑、GUI 推到 M2 初；sidecar（M2-7）若延期，M2 先用 in-process 参赛，sidecar 作为稳定性增强。
- **每日集成**：能力包保持"随时可 build、单测全绿"，每完成一个包即接入，不攒大爆炸式集成。

## 5 质量保障

| 手段 | 要求 |
|------|------|
| 单元测试 | 每个能力包 vitest 覆盖核心分支（模型降级、截断、白名单、预算、解析、checkpoint） |
| 契约测试 | `@chatvein/testing` 提供 mock 模型/沙箱/时钟；core 用 mock 跑确定性场景 |
| 架构红线 | CI 断言 `packages/chatvein/**` 不 import electron；app forge 模块不直接 import langchain |
| 端到端 | 每个里程碑至少 1 个固定小需求脚本一键跑通，纳入 `forge regression` |
| 代码评审 | 关键节点（状态机边条件、护栏、sidecar 协议）自审 + 留 docs |

## 6 风险与应对（进度视角）

| 风险 | 概率 | 应对 |
|------|------|------|
| 9/7 才开课，窗口短 | 高 | M0 先搭骨架不等课程；M1 收口"能跑通"，P1 全砍 |
| LangGraph 学习/调试成本 | 中 | M1-7 先跑官方最小例；状态机保持节点少、边简单 |
| sidecar 协议复杂拖慢 | 中 | 先 in-process 参赛，sidecar 作为增强；协议用最简 stdio JSON |
| Token 超支 | 中 | 截断/压缩/文件索引优先做（M1-3）；默认串行；预算护栏硬熔断 |
| 环境差异 | 中 | M0 摸清沙箱；verifier 在与赛事一致的命令上解析 |

## 7 交付物清单（一期结束时）

1. `packages/chatvein/` 下 10 个能力包（common/core/models/tools/sandbox/compiler/orchestrator/context/verifier/observability）+ `service`，全部 build/test 通过。
2. `forge` CLI：`run / resume / preview / regression`。
3. 改造后的 `app/`：Forge 控制台（任务树/时间线/诊断/干预/续跑）。
4. `config/forge.config.ts` 配置模板与加密密钥存储。
5. `runs/` 运行产物规范与一份示例 run（含 report.md）。
6. `docs/phase1/` 三份文档（本套）+ M0 基线与沙箱规格笔记。
