## 1 里程碑总览

对齐总 PRD 第 9 节；**分两轨并行**——Forge 初赛轨（M0–M3）与 Chat 产品轨（CP0–CP2），共用底层能力包、编排形态不同。

| 里程碑 | 时间 | 目标 | 出口标准（Definition of Done） |
|--------|------|------|-------------------------------|
| **M0 基线与脚手架** | 9/3–9/6 | 报名 + 实测基线 + 搭好 `@chatvein/*` 空包骨架 | `baseline.json` 落盘；能力包可 build/test；CLI 空命令可跑 |
| **M1 骨架打通** | 9/7–9/13 | 单任务"写代码→跑测试→修"最小闭环，控制台能看 trace | CLI 对小需求端到端跑通一次；app 能显示 Forge 事件流 |
| **M2 能力成型** | 9/14–9/20 | 完整状态机 + 需求编译 + 上下文/预算 + 断点续跑 + sidecar | 练习赛题跑通；三项指标 ≥/优于基线；续跑验证通过 |
| **M3 初赛演练** | 9/21–9/30 | 每日全量演练 + 调优 | 黑盒通过率 ≥85%，冲 Top 20 |
| **CP0 对话运行时** | M1 末–M2 初 | `@chatvein/agents` + LangGraph ReAct 最小闭环 | 单 Agent 可调工具；trace 可见 |
| **CP1 普通对话产品化** | M2 中–M2 末 | app 聊天切 agents；流式 + Markdown（08 文档） | 对话页 ReAct + 思考/工具事件流 |
| **CP2 群聊与记忆** | M3 后 / 第二期初 | groups free + 个人记忆 | 建群 @ 驱动；记忆检索接入 |

> **双轨原则**：Forge 轨（M*）**不阻塞**初赛交付；Chat 轨（CP*）在 M1-4 `tools` + M1-3 `context` 就绪后启动，**复用同一套 models/tools/context/observability**，编排层用 LangGraph 但图不同（见 §1.1）。M1 严格收口在 Forge「能跑通」；CP 任务可并行，不砍 P1 并行/Docker 等仍后置。

### 1.1 双轨与 LangGraph 分工（不自研循环）

| 轨 | 包 | LangGraph 形态 | 用途 |
|----|-----|----------------|------|
| **Forge 轨** | `@chatvein/orchestrator` | `StateGraph`（plan→implement→verify→…） | 自动写代码-测试-修复（参赛主路径） |
| **Chat 轨** | `@chatvein/agents` | `createReactAgent` / tool-calling 图 | 普通对话、群成员单次发言（ReAct） |
| **Chat 轨** | `@chatvein/groups` | supervisor / 群消息图 | **用户建群**后的 @ 路由、收敛（P0+）；非 Agent 自发拉群 |

**不从零开发 Agent 循环**：Thought→Action→Observation 由 LangGraph/LangChain 提供；`@chatvein/*` 负责角色加载、工具绑定、记忆、trace、预算护栏与 Cordis 装配。模型层保留 `ChatModelLike` + fetch 直连（可测）与 `@langchain/openai` 适配（给 LangGraph 喂模型）并存，见 [`04-依赖选型.md`](./04-依赖选型.md)。

## 2 包建设顺序（依赖驱动）

### 2.1 Forge 轨（初赛）

```
common  →  models ┐
                  ├→ tools ┐
                  │        ├→ sandbox ┐
                  │        │          ├→ verifier ┐
                  └→ context ┘        │            ├→ orchestrator ┐
                  compiler ───────────┘            │               ├→ core → service
                  observability（横切，最早搭总线） ┘               ┘            │
                                                                                 └→ app（Forge GUI）
```

施工顺序：`common` → `observability` → `models` → `tools`+`context` → `sandbox` → `verifier` → `compiler` → `orchestrator` → `core` → `service(CLI)` → 端到端 → `service(sidecar)` → `app(forge)`。

### 2.2 Chat 产品轨（与 Forge 共用底座）

```
models ──┐
tools  ──┼→ agents ─→ groups
context──┤      │        │
memory ←─┼─ vector ┘    │
observability（横切）────┘
         ▲
         └── 全部 Cordis 插件挂 @chatvein/core；app chat/group 模块薄调用
```

施工顺序（**M1-4 tools 完成后可启动 CP0**）：`agents`（createReactAgent）→ app `chat:*` 切 agents → [`08-流式对话`](../design/08-流式对话与Markdown渲染.md) → `memory`+`vector` → `groups`。

> 新增包：`agents`、`groups`、`memory`、`vector`（见 [`../design/01-核心骨架.md`](../design/01-核心骨架.md) §3）。与 Forge 11 包并列，同样纯 Node、零 electron。

## 4 关键路径与缓冲

- **Forge 关键路径**：common → models/tools → orchestrator → core → service(CLI) 端到端（M1）→ sidecar + app(forge)（M2）。
- **Chat 关键路径**：models/tools/context → agents(createReactAgent) → app chat 切换（CP0–CP1）；memory/vector → groups（CP2）。
- **缓冲策略**：M1 的 app Forge GUI（M1-10）若紧张，可先用 CLI 验证；sidecar（M2-7）若延期，M2 先用 in-process 参赛。Chat 轨 CP1 不挡 Forge M2 出口；app 临时 `chat.service` 直连可保留至 CP1-5 完成。
- **每日集成**：能力包保持"随时可 build、单测全绿"，每完成一个包即接入，不攒大爆炸式集成。

## 5 质量保障

| 手段 | 要求 |
|------|------|
| 单元测试 | 每个能力包 vitest 覆盖核心分支（模型降级、截断、白名单、预算、解析、checkpoint） |
| 契约测试 | `@chatvein/testing` 提供 mock 模型/沙箱/时钟；core 用 mock 跑确定性场景 |
| 架构红线 | CI 断言 `packages/chatvein/**` 不 import electron；**app forge 模块**不直接 import langchain；**app chat/group 模块**不内嵌 LangGraph，只调 `@chatvein/agents|groups` |
| 端到端 | 每个里程碑至少 1 个固定小需求脚本一键跑通，纳入 `forge regression` |
| 代码评审 | 关键节点（状态机边条件、护栏、sidecar 协议）自审 + 留 docs |
