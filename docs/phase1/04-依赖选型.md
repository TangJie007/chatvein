# Forge 第一期 · 依赖选型说明

> 版本：v1.1 ｜ 日期：2026-09-03
> 配套：[`02-方案设计.md`](./02-方案设计.md)（包结构）、[`03-开发计划书.md`](./03-开发计划书.md)（WBS）
> 变更：v1.1 引入 `@deepseek-ai/cordis` 作为 harness 插件运行时标准。
> 本文记录 `@chatvein/*` Harness 能力包与壳侧的**第三方依赖选型、版本、用途、理由与备选方案**。

---

## 1 选型原则

1. **能力包纯 Node、零 `electron` 依赖**：所有第三方库必须能在普通 Node 进程（`@chatvein/service` sidecar/CLI）里运行，不依赖 Electron 运行时。CI 加断言兜底。
2. **尽量最新稳定版**：2026-09 时点的最新稳定版；避免 alpha/beta（electron-vite 6、Node 26 这类未转正的不追）。
3. **可替换、可注入**：模型、沙箱、存储等通过 `@chatvein/common` 的最小接口（`ChatModelLike`、`SandboxProvider`）解耦，LangChain 等框架只在适配层出现，关键路径可绕过。
4. **少即是多**：P0 只引入"现在就要用"的依赖；BM25、Docker 驱动、GUI 自动化等 P1 能力的依赖**暂缓安装**，触发条件见第 5 节。
5. **原生模块最小化**：优先 WASM/纯 JS；确需原生（sqlite）放在 sidecar 进程，不进 Electron 主进程 bundle。

包管理：pnpm 11 workspace，`packageManager: pnpm@11.22.0`，`engines.node: >=22.12.0`。

### 依赖归属图（谁依赖谁）

```
common      ← zod
observability← common, pglite
models      ← common, @langchain/core, @langchain/openai, zod
context     ← common
tools       ← common
sandbox     ← common
compiler    ← common, zod
verifier    ← common
orchestrator← common, @langchain/core, @langchain/langgraph
core        ← common + 上述能力包 + @deepseek-ai/cordis(+loader/include/timer)
```

跨包只依赖 `@chatvein/common` 的**接口**（如 `ChatModelLike`），不直接 import 别的能力包的具体实现；由 **Cordis Context** 在 `core` 里 `plugin()` 装配并暴露为服务。

## 4 关键选型决策与备选

| 决策点 | 选定 | 备选 | 理由 |
|--------|------|------|------|
| **内嵌沙箱** | **独立工作区 + 受限 `child_process`（`local`）** | Docker / V8 isolate / 云沙箱 | **已锁定 P0**：完全内嵌、零外部依赖、Windows 友好、可跑真 npm/git；Docker 仅 P1 对齐赛事；见 [`../design/07-沙箱方案.md`](../design/07-沙箱方案.md) |
| **插件运行时** | **`@deepseek-ai/cordis`（+ loader/include/timer）** | 上游 `cordis` / 自研装配器 / Nest-like DI | 本软件插件化标准；可逆 Fiber、与 DSH 同族；全家桶 `@deepseek-ai/cordis-*`，不混装上游 |
| 编排框架 | LangGraph.js | 自研状态机 / Mastra / Vest | PRD 指定；checkpoint/图/人在环回路原生；**Cordis 不替代 LangGraph**（前者管插件生命周期，后者管任务图） |
| 模型接入 | `@langchain/openai`（OpenAI 兼容） | 直接 fetch 网关 / ai-sdk | 一个适配器接多家；关键路径保留绕过框架直连网关的能力（R1） |
| Schema/校验 | zod 4 | typebox / valibot | LangGraph peer 要求；TS 体验最好 |
| 嵌入式存储 | PGlite（WASM） | embedded-postgres（真实二进制）/ sqlite | 3MB、无进程、跨平台无杀软问题；embedded-postgres 需带 ~100MB 平台二进制 |
| Checkpoint | langgraph-checkpoint-sqlite（better-sqlite3） | 内存 saver / node:sqlite 自研 saver | 官方维护、零自研；原生模块只在 sidecar（系统 Node）用 |
| CLI | cac | commander / yargs | 轻、TS 友好 |
| 打包 | tsup | tsc / unbuild / rolldown | 与 electrum 包统一，双格式 + dts 一把梭 |
| 测试 | vitest | jest / node:test | 与 vite 生态一致、快、ESM 原生 |

### Cordis 运行位置（重要）

- Cordis `Context` 只在 **sidecar / CLI（系统 Node）** 或 Electron 主进程 **in-process harness** 内创建；由 `@chatvein/core` 持有根 Context。
- **禁止**渲染进程、preload、`@electrum/*` import `@deepseek-ai/cordis`。
- **禁止**同时依赖上游 `cordis` / `@cordisjs/*`（两套 Context 会冲突）。
- 赛前锁小版本；升级 `@deepseek-ai/cordis*` 需跑 `pnpm test:harness`。

### better-sqlite3 / node:sqlite 的运行位置（重要）

- `@langchain/langgraph-checkpoint-sqlite` 依赖**原生** `better-sqlite3`。它安装在 `@chatvein/service`，运行在 **sidecar（系统 Node 24）**，有预编译二进制，开箱即用。
- **不要**把它打进 Electron 主进程 bundle（electron-vite 需 externalize + asar unpack + ABI 对齐，坑多）。
- Electron 主进程的**模式 A（in-process）**若要 checkpoint，用 Node 24 内置的 `node:sqlite` 自写一个薄 saver，或直接走 sidecar（推荐）。

## 6 版本与升级策略

- **锁定**：`pnpm-lock.yaml` 提交；CI/演练用 `pnpm install --frozen-lockfile` 保证可复现。
- **原生构建审批**：`pnpm-workspace.yaml` 的 `allowBuilds` 显式允许 `electron`、`esbuild`、`better-sqlite3`（pnpm 11 默认禁 postinstall）。
- **Electron 二进制**：全新安装若 Electron 下载慢，设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`。
- **升级节奏**：赛前冻结依赖（只打补丁）；LangChain/LangGraph/`@deepseek-ai/cordis*` 小版本升级先跑 `pnpm test:harness` 再合。
- **可复现记录**：每次 run 的报告里写入 node 版本、依赖版本（`pnpm list --depth 0`）、模型版本、配置快照。
