## 三、跨文档指针写法

合并后所有章节号沿用原文档编号，因此跨篇引用要带「分区名」：

- `架构与目录.md §架构总览 5`＝「架构总览」部分第 5 节；`§项目目录 2.3` 同理。
- `Agent与功能.md §Agent流水线 12`＝工具矩阵；`§功能清单 3` ＝内置工具一节。
- `机制详解.md §短期记忆 6`＝窗口策略；`§工作区模型` 无编号，直接用节名。
- `运维手册.md §配置总表 2`＝执行与沙箱相关开关。

## 四、维护约定

1. 文档与代码同一次改动里更新；新增/改名接口必须同步 `src/api/*.ts` 与本索引。
2. 同一事实只在一处解释，其余位置留一行指针（如「见 `Agent与功能.md` §Agent流水线 7」）；遇到重复内容先删后加指针，不要再扩写。
3. 标注日期与状态，便于判断是否过期；发现滞后优先改代码侧注释，再回来修文档。
4. 不再新增零散 `.md`：新材料并入本表对应文档的对应分区，确需新建才登记。
5. 文档里的命令与路径必须**可执行**（文件名、脚本名、参数以代码为准）；发现失效引用当次修掉。
6. `backend/tests/test_config.py` 会扫 `运维手册.md` 的「配置总表」分区：代码新增 `CHATVEIN_*` 开关必须同步加表。
