# 记忆方案设计（结构化 · 省 Token · 命中缓存）

> 版本：v0.1 ｜ 日期：2026-09-03
> 上位：[`01-核心骨架.md`](./01-核心骨架.md) ｜ 向量底座：[`04-向量存储架构.md`](./04-向量存储架构.md) ｜ 群组：[`05-群组记忆架构.md`](./05-群组记忆架构.md)
> 目标：记忆既要**结构清晰、可检索**，又要**尽量少占 token**，还要**最大化命中模型的 prompt 缓存**。

---

## 1 记忆分层（4 层）

| 层 | 内容 | 生命周期 | 存哪 | 是否进上下文 |
|----|------|---------|------|--------------|
| **工作记忆 working** | 当前对话/当前轮的消息、工具结果 | 单次会话 | 内存（LangGraph state） | 直接进（受截断） |
| **情景记忆 episodic** | 历史消息、工具调用、事件（"发生过什么"） | 长期 | PGlite + JSONL trace | 检索后按需进 |
| **语义记忆 semantic** | 提炼出的事实、偏好、结论、用户画像 | 长期，可更新 | PGlite（带 embedding） | 摘要/命中后进 |
| **程序记忆 procedural** | 规则、技能、工作流、"以后遇到 X 就 Y" | 长期，可沉淀 | PGlite + 角色/群设定 | 稳定前缀进 |

关键原则：**原始流水（episodic）全量落盘但不直接塞上下文**；进上下文的是**检索命中的少量片段 + 压缩摘要**。

## 2 记忆数据结构

```ts
interface MemoryItem {
  id: string
  scope: 'personal' | 'group' | 'global'     // 见 05 文档
  ownerId: string                             // roleId / groupId / 'global'
  kind: 'fact' | 'preference' | 'decision' | 'rule' | 'summary' | 'episode-ref'
  content: string                             // 给人/检索用的原文/摘要
  embedding?: number[]                        // 向量（04 文档）
  importance: number                          // 0..1，召回与保留权重
  source?: { messageId?: string; runId?: string }
  tags?: string[]
  validUntil?: number                         // TTL，过期降权/遗忘
  contentHash: string                         // 内容寻址，用于缓存稳定（见 §5）
  createdAt: number
  updatedAt: number
}
```

- `episode-ref` 不存全文，只存指针（指向 trace/payload 文件 + 一句话摘要），需要时再精确读取——和 Forge 的"文件索引替代全文"思路一致。
- `importance` 由写入时启发式（是否含决策/数字/用户明确要求）+ 弱模型打分决定，影响召回排序与淘汰。

## 3 读写管线

### 3.1 读（召回，进上下文前）

```
query（当前用户消息 / 当前任务）
  → 改写：弱模型把口语 query 改写成检索串（可选，省 token 用短串）
  → 混合检索（向量 + BM25/关键词）@chatvein/vector
       · personal：该角色/用户自己的记忆
       · global：全局规则/技能
       · （群里再加 group 记忆，见 05）
  → 合并去重 → 按 importance × 相关度 × 时效 排序 → 取 top-k（k 很小，如 5~8）
  → 渲染成紧凑"记忆块"（见 §4）
```

召回数量受**预算**约束：`@chatvein/context` 根据剩余 token 预算动态定 k，宁可少召回也不爆上下文。

### 3.2 写（沉淀，异步、批处理、省 token）

- **即时写**：工具结果、消息直接落 episodic（不调模型，零额外 token）。
- **异步提炼**：会话结束 / 每完成一个任务 / 每 N 轮，用**弱模型**把这段历史压成 semantic 记忆（事实/决策/规则），写入 PGlite 并生成 embedding。
- **去重/合并**：用 `contentHash` + 向量近邻判重，同类记忆 upsert（更新而非堆叠），避免记忆膨胀。
- **巩固 consolidation**：定期把多条细碎 semantic 再归纳成更少、更高层的条目（层级摘要）。

> 写路径尽量用弱模型、批量、异步，不阻塞主循环；提炼本身的 token 计入预算并可在比赛时调低频率。

## 4 省 Token 的具体手段

1. **检索代替全量**：上下文里永远只放 top-k 命中记忆 + 摘要，不放历史全文。
2. **层级摘要（rolling summary）**：旧对话 → 段落摘要 → 会话摘要 → 长期事实，越老越压缩；需要细节时用 `episode-ref` 回查。
3. **结构化短格式**：记忆块用紧凑模板（`[事实] … / [规则] … / [决定] …`），不带寒暄和推理过程。
4. **文件/代码用索引**：代码记忆只存"路径 + 符号 + 一句话职责"，需要时再读（复用 Forge file index）。
5. **错误只存关键帧**：失败经验存"错误类型 + 责任文件 + 修法"，不存整份日志。
6. **遗忘/降权**：低 importance、过期、长期未命中的记忆降权或归档，控制召回噪声。
7. **群聊特殊处理**：不是每个角色都看全部群消息（见 [05 文档](./05-群组记忆架构.md)）。

## 5 命中 Prompt 缓存的布局（重点）

主流网关（OpenAI / Anthropic / 兼容网关）对**前缀完全一致**的 prompt 片段做缓存。记忆系统必须配合，否则每次召回都把缓存打乱。

### 5.1 上下文分段，按"稳定性"排序

```
┌─ 稳定前缀（跨轮不变，缓存命中区） ────────────────┐
│ 1. 系统/平台指令                                   │
│ 2. 角色人设 persona                                │
│ 3. 工具定义 tool schemas                           │
│ 4. 程序记忆：长期规则/技能（变动极少）              │
│ 5. 语义记忆摘要块（Memory Digest，按 §5.2 稳定化）  │
├─ 易变后缀（不指望缓存） ──────────────────────────┤
│ 6. 本轮检索到的少量情景片段                        │
│ 7. 最近 N 条对话/工具结果（working memory）        │
│ 8. 当前用户输入                                    │
└──────────────────────────────────────────────────┘
```

原则：**越稳定的越靠前，越易变的越靠后**。缓存从前往后命中，易变内容放在最后不会击穿前面的缓存。

### 5.2 让"记忆摘要块"保持稳定

记忆块是最容易破坏缓存的部分（每次召回结果不同）。对策：

- **分两块**：把**长期 semantic digest**（变化慢、全量排序固定）放稳定前缀；把**本轮临时召回**（每轮不同）放易变后缀。
- **内容寻址 + 版本化**：digest 由 `contentHash` 集合生成，只有当长期记忆真的增删改时才变；没变就逐字节复用，缓存继续命中。
- **固定顺序**：digest 内条目按 `id`/重要性**确定性排序**，不按当轮相关度排序（相关度排序只用于易变的临时召回块）。
- **显式缓存断点**：对支持显式缓存的网关，在"稳定前缀末尾"打 cache breakpoint（如 Anthropic `cache_control`），让模型缓存这一整段。
- **角色/工具定义稳定**：同一角色的 persona、工具集在会话内不变；要换工具/人设就开新会话，避免中途变更击穿缓存。

### 5.3 群聊里的缓存

- 每个角色有**自己的稳定前缀**（自己的 persona + 自己的程序/长期记忆），跨多次发言复用；
- 变化的"群最近消息"放最后；
- 这样同一个角色在群里第 N 次发言时，其前缀仍命中缓存（详见 [05 文档](./05-群组记忆架构.md)）。

## 6 与包/网关的落点

| 能力 | 落点 |
|------|------|
| 记忆读写/提炼/巩固 | 新增 `@chatvein/memory`（`recall()` / `write()` / `consolidate()`） |
| 向量 + BM25 检索 | `@chatvein/vector`（[04 文档](./04-向量存储架构.md)） |
| 预算动态定 k、截断 | `@chatvein/context` |
| 长期/原始流水存储 | PGlite（memories 表）+ JSONL trace |
| 模型 | 提炼/改写用 weak 档，召回排序无需模型 |
| 缓存断点 | `@chatvein/models` 在组装请求时按 §5 放置 cache 标记（视网关支持） |

## 7 验收要点

1. 长期记忆 digest 在**连续多轮无新增记忆时逐字节一致**（可用 hash 校验），保证缓存命中。
2. 单次召回注入上下文的记忆 token 有上限且随预算自适应。
3. 关掉模型也能落 episodic（写路径零额外 token）。
4. 同一条事实不重复入库（contentHash/近邻去重生效）。
5. trace 里能看到每次召回了哪些记忆、命中缓存的前缀长度（用于复盘 token）。
