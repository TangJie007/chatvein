# 启发式规则路由层（L1 / L1.5）

> 版本：v0.4 ｜ 日期：2026-09-04  
> **决策状态：已落地（R0–R2 核心 + 目录分层）**  
> 变更：v0.2 拉群边界；v0.3 实现；v0.4 `routing/{l1,l2,locales}` + `common/{core,forge,chat}`  
> 上位：[`01-核心骨架.md`](./01-核心骨架.md)、[`02-agent循环方案.md`](./02-agent循环方案.md)  
> 关联：[`03-记忆方案.md`](./03-记忆方案.md)（记忆 BM25 分轨）、[`../phase1/04-依赖选型.md`](../phase1/04-依赖选型.md)  
> 排期：建议挂 **CP1 末 / CP2 初**

**实现入口**：`packages/chatvein/agents/src/routing/`（`pipeline` → L1 → 可选 L2）；契约在 `@chatvein/common` 的 `chat/route`。app `chat.service` 在 ReAct 前调用并推送 `chat:event` 的 `route` + thinking 摘要。

用户消息进入 Agent / 群路由之前，用**无 LLM 的确定性管线**判断复杂度与执行策略：能确定的毫秒级短路，吃不准的保守默认或交 L2（弱模型分类器，本文只留接口）。

## 1 决策摘要

| 关注点 | 选定 | 说明 |
|--------|------|------|
| **目标** | 分流 `modelTier` / `tools` / `maxSteps` / 是否 recall / 是否允许生子 Agent；可选 **提示用户** 拉群 | 省 token、降延迟；**拉群仅用户在客户端操作，Agent 不得自发建群** |
| **L1 规则引擎** | **`json-rules-engine`** | JSON 可配置、无 `eval`、有 priority；facts = 特征上下文 |
| **L1.5 先例检索** | **内存 BM25**（`wink-bm25-text-search`） | 对**标注问句样例库**检索 + 标签投票；与记忆 BM25 **分索引** |
| **特征抽取** | 自研纯函数 + `es-toolkit` | 长度/围栏/路径/slash 等零成本信号；不引重 NLP |
| **输出契约** | `RouteDecision`（`@chatvein/common`） | zod 校验；下游 agents / models / BudgetGuard 消费 |
| **置信策略** | 假阳性严控：不确定 → `confident=false` | 宁可进默认 medium，不可把改代码判成无工具快答 |
| **L2** | 预留接口，一期可不实现 | 仅消费 L1 的 `unknown` / 低置信灰区 |
| **包归属** | `@chatvein/agents` 内 `routing/`（或日后抽 `@chatvein/routing`） | app 只调 `agents`；纯 Node、可单测 |

> 红线：本层**零 LLM、零磁盘大查询、零全量记忆扫描**；BM25 仅查常驻内存的小先例库。  
> **协作边界**：**拉群 / 建群 / 升级成群 = 用户在客户端发起**（UI 可据 `hintUserCreateGroup` 提示，但点确认、选角色、建群均在 app）；**Agent 侧自发的多智能体 = 创建若干子 Agent**（`allowSubAgents`），不是拉群。详见 [01 §5.0](./01-核心骨架.md)。

## 2 在流水线中的位置

```
用户消息 + 会话轻量态
        │
        ▼
┌──────────────────────────────────────────────┐
│  HeuristicRouter.route(input)                │
│    1. extractFacts(input)     → HeuristicCtx │  μs
│    2. json-rules-engine.run   → tags/score/  │  <1ms
│       overrides / terminal                   │
│    3. [若未 terminal 且灰区]                  │
│       bm25.search(query) → 投票加权          │  1–5ms
│    4. materialize(RouteDecision)             │
└──────────────────────────────────────────────┘
        │
   ┌────┼─────────┬──────────────┐
   ▼    ▼         ▼              ▼
 本地  快答      默认/全量 ReAct     escalate
命令  weak      （可 allowSubAgents） → L2；UI 可提示用户拉群
     无工具     （按 policy）           （绝不自动建群）
```

与现有组件关系：

| 组件 | 关系 |
|------|------|
| `@chatvein/models` `ModelRouter` | **不**做意图判断；只执行 `policy.modelTier` |
| `@chatvein/agents` ReAct | 按 `tools` / `maxSteps` 裁剪工具与 BudgetGuard；`allowSubAgents` 时可由运行时**创建子 Agent**（非建群） |
| `@chatvein/groups` | 仅当**用户已建群**且处于群会话：`@mention` 等由 L1 **terminal 短路**交给群路由；L1 **永不**调用建群 API |
| `@chatvein/memory` 召回 | `policy.memoryRecall === false` 时可跳过；**记忆索引 ≠ 先例索引** |
| `@chatvein/observability` | 每条消息落 `route.l1` 事件（reasons / score / band / bm25Hits） |

普通对话数据流（相对 [01 §7.1](./01-核心骨架.md)）在 `Agent.handle` 前插入：

```
用户消息
  → routing.route(...)           # 本文
  → （可选）memory.recall        # 受 policy.memoryRecall 约束
  → 组装上下文 + models.routeForRole / 按 policy.modelTier 覆盖
  → ReAct（工具集与步数受 policy 约束；allowSubAgents 时可创建**子 Agent**）
  → （hintUserCreateGroup / hintUserForge 只随事件回 UI，不在此建群/派单）
```

## 3 核心类型

放 `@chatvein/common`（主/渲染/agents 共享），zod schema 同源导出。

```ts
/** 复杂度分档（Chat 侧；对齐 Forge TaskComplexity 语义族） */
export type ComplexityBand =
  | 'trivial'    // 寒暄/确认/本地可答
  | 'simple'     // 短问答，少步或无工具
  | 'standard'   // 默认单 Agent ReAct
  | 'complex'    // 强模型 / 多步 / 可允许创建子 Agent
  | 'unknown'    // 灰区：保守默认或交 L2

/** 工具策略：none 禁用；full 完整（仍受角色白名单）；unknown = L1 不确定，交 L2 */
export type ToolPolicy = 'none' | 'unknown' | 'full'


export interface RoutePolicy {
  modelTier: 'weak' | 'medium' | 'strong'
  tools: ToolPolicy
  maxSteps: number
  memoryRecall: boolean
  /**
   * Agent 运行时是否允许创建若干**子 Agent**（分工/并行视角）。
   * 这是 Agent 可自发的多智能体形态；**不是**拉群。
   */
  allowSubAgents?: boolean
  /**
   * 仅给 **客户端 UI** 的提示：「要不要拉群讨论」。
   * 建群/选人/升级会话必须由用户操作完成；routing / agents **禁止**调用 group:create。
   */
  hintUserCreateGroup?: boolean
  /** 仅打标给 UI；派单 Forge 由用户确认，不自动跑图 */
  hintUserForge?: boolean
}

export interface Bm25Hit {
  id: string
  score: number
  band: ComplexityBand
  tools?: ToolPolicy
}

export interface RouteDecision {
  band: ComplexityBand
  /** true 才允许走快路径短路；false 必须保守或交 L2 */
  confident: boolean
  policy: RoutePolicy
  score: number
  reasons: string[]
  /** 命中的规则 id（json-rules-engine event） */
  ruleIds: string[]
  bm25Hits?: Bm25Hit[]
  /** terminal 硬短路（slash / @ / 空消息） */
  terminal?: {
    kind: 'slash' | 'mention' | 'empty' | 'local_command'
    payload?: Record<string, unknown>
  }
}
```

**合成优先级（高 → 低）**

1. `terminal` 硬短路（规则 `terminal: true`）→ 直接返回，跳过 BM25  
2. 规则强制 `override.band` / `override.policy.*`  
3. BM25 投票（仅当未 terminal，且规则未标 `skipBm25`）  
4. `score` 阈值映射默认 policy  
5. 仍灰 → `band=unknown`，`confident=false`，policy = 保守默认（见 §7）

## 4 特征上下文 `HeuristicCtx`（facts）

`json-rules-engine` 的 facts 全部来自同步纯函数，**禁止**在 fact 函数里做 IO / LLM。

```ts
export interface HeuristicCtx {
  // —— 文本 ——
  text: string
  textNorm: string
  charLen: number
  tokenEst: number          // 中文≈字数，英文≈ ceil(len/4)
  lang: 'zh' | 'en' | 'mix' | 'unknown'

  // —— 结构信号 ——
  hasCodeFence: boolean
  codeFenceCount: number
  hasUrl: boolean
  hasPathLike: boolean      // ./src、盘符、*.ts 等
  hasMention: boolean
  mentions: string[]
  slashCmd?: string         // 首 token 为 /xxx
  questionMarkCount: number
  listItemCount: number     // 1. / - / * 列表项

  // —— 词典命中（预计算布尔，规则只读布尔）——
  hitGreetingOnly: boolean  // 整句几乎只有寒暄（防「你好，帮我设计…」）
  hitTaskVerb: boolean      // 实现/修复/搜索/运行…
  hitToolVerb: boolean
  hitNegateTool: boolean    // 不要改文件 / 别搜索
  hitMultiStep: boolean     // 然后/接着/第一步…
  hitCompare: boolean       // 哪个更好/选型/权衡 → 倾向 allowSubAgents
  hitGroupIntent: boolean   // 用户口述「拉群/建群讨论」→ 仅 hintUserCreateGroup（UI）
  hitMultiAgentNeed: boolean // 多方视角/并行子任务（无「建群」措辞）→ allowSubAgents
  hitForgeIntent: boolean   // 去实现并测/写代码跑测试 → hintUserForge
  hitCorrection: boolean    // 不对/重来/改一下（指代上文）

  // —— 会话轻量态（内存，不读全历史）——
  turnIndex: number
  lastBand?: ComplexityBand
  lastAssistantHadTools: boolean
  recentFailure: boolean
  activeMode: 'chat' | 'group' | 'forge'
  forceTier?: 'weak' | 'medium' | 'strong'
}
```

### 4.1 特征抽取要点

| 信号 | 实现要点 |
|------|----------|
| `hitGreetingOnly` | 去掉标点后整句 ∈ 寒暄词典，或「寒暄 + 可选语气词」；**不得** `includes('你好')` 即真 |
| `hasPathLike` | 正则：扩展名、`/` `\` 路径片段、常见配置文件名 |
| `hasCodeFence` | \`\`\` 成对计数 |
| `slashCmd` | `^/([a-zA-Z][\w-]*)` |
| 词典 | 配置加载为 `Set`；中英分桶；否定词优先于工具词 |

特征模块：`routing/l1/features.ts`；词典：`routing/locales/{zh,_common}.json`（一期仅中文）。

## 5 `json-rules-engine` 设计

### 5.1 为何用它

- 规则 JSON 可落盘、可热更新（改阈值不必改代码）  
- `priority` + 条件嵌套（`all` / `any`）覆盖「硬短路 / 加分 / 降档」  
- 无 `eval`，适合进 harness  
- 与「自研有序 if 表」比：规则变多、产品要调参时更可维护  

否决：自研完整规则引擎；`rools`（过重）；nlp.js（偏 L2/ML，不是纯规则）。

### 5.2 事件约定

每条规则 `event.type` 使用统一前缀，`params` 为结构化副作用：

```ts
type RuleEventType =
  | 'route.terminal'      // 硬短路
  | 'route.override'      // 强制 band / policy 字段
  | 'route.bump'          // score += delta
  | 'route.tag'           // 仅记 reasons / 建议标

interface RuleEventParams {
  ruleId: string
  reason: string
  scoreDelta?: number
  band?: ComplexityBand
  policy?: Partial<RoutePolicy>
  terminal?: RouteDecision['terminal']
  skipBm25?: boolean
  confident?: boolean
}
```

引擎跑完后，由 `materialize(events, ctx)` **归并**（引擎本身不产出最终 `RouteDecision`）。

### 5.3 规则目录（P0 最小集）

| priority | ruleId | 条件（示意） | event |
|----------|--------|--------------|-------|
| 1000 | `empty` | `charLen === 0` | terminal empty |
| 990 | `slash` | `slashCmd` 存在 | terminal slash |
| 980 | `mention_group` | `activeMode==group && hasMention` | terminal mention |
| 900 | `force_tier` | `forceTier` 存在 | override modelTier |
| 800 | `greeting_trivial` | `hitGreetingOnly && !hitTaskVerb && charLen≤30` | override trivial + weak + tools none + skipBm25 + confident |
| 700 | `negate_tools` | `hitNegateTool` | override tools none（锁定） |
| 600 | `code_fence` | `hasCodeFence` | bump +25 |
| 590 | `path_like` | `hasPathLike` | bump +20 |
| 580 | `tool_verb` | `hitToolVerb && !hitNegateTool` | bump +20；policy tools=`unknown`（交 L2） |
| 570 | `task_verb` | `hitTaskVerb` | bump +15 |
| 560 | `multi_step` | `hitMultiStep \|\| listItemCount≥3` | bump +15 |
| 550 | `compare` | `hitCompare` | bump +20；`allowSubAgents` |
| 545 | `multi_agent_need` | `hitMultiAgentNeed` | bump +15；`allowSubAgents` |
| 540 | `group_intent` | `hitGroupIntent` | **仅** `hintUserCreateGroup`（不建群、不生子 Agent） |
| 530 | `forge_intent` | `hitForgeIntent` | `hintUserForge`；bump +25 |
| 520 | `correction` | `hitCorrection \|\| recentFailure` | bump +25；禁止降到 trivial |
| 510 | `long_text` | `charLen>200 / >800 / >2000` | bump +10/+20/+30 |
| 400 | `inherit_last` | `turnIndex>0 && hitCorrection==false && charLen<20 && lastBand` | bump 继承 lastBand 权重（防「再详细点」掉 trivial） |
| 100 | `default_floor` | 总是可匹配的低优（可选） | 无 |

规则 JSON 示例（节选）：

```json
{
  "name": "greeting_trivial",
  "priority": 800,
  "conditions": {
    "all": [
      { "fact": "hitGreetingOnly", "operator": "equal", "value": true },
      { "fact": "hitTaskVerb", "operator": "equal", "value": false },
      { "fact": "hitToolVerb", "operator": "equal", "value": false },
      { "fact": "charLen", "operator": "lessThanInclusive", "value": 30 }
    ]
  },
  "event": {
    "type": "route.override",
    "params": {
      "ruleId": "greeting_trivial",
      "reason": "greeting_only",
      "band": "trivial",
      "confident": true,
      "skipBm25": true,
      "policy": {
        "modelTier": "weak",
        "tools": "none",
        "maxSteps": 0,
        "memoryRecall": false
      }
    }
  }
}
```

配置路径建议：`config/chat.heuristic.rules.json`（默认规则打进包，用户可覆盖合并）。

### 5.4 自定义 operator（按需）

内置 `equal` / `greaterThan` 等通常够用。若需「字符串 ∈ 集合」可注册：

- `inSet`：`fact` 为 string，`value` 为 string[]  
- `bitAnd`：少用，优先在特征阶段算成布尔  

保持 operator 面小，逻辑尽量前移到 `extractFacts`。

## 6 BM25 先例层（L1.5）

### 6.1 定位

- **做什么**：用当前 `text`（或轻量规范化串）检索**标注样例**，对 `band` / `tools` 做加权投票，修正灰区。  
- **不做什么**：不检索用户记忆、不检索 trace 全文、不替代硬规则。  
- **何时跑**：无 `terminal`；无 `skipBm25`；且规则合成后 `confident !== true` 或 score 落在灰区。

### 6.2 语料 schema

```ts
interface RoutePrototype {
  id: string
  text: string                 // 标注问句（检索字段）
  band: ComplexityBand         // 不含 unknown
  tools: ToolPolicy
  lang?: 'zh' | 'en'
  tags?: string[]              // 可选：debug / domain
}
```

- 语料文件：`config/chat.route.prototypes.jsonl`（或 JSON 数组）  
- 规模目标：P0 **200–500** 条；上限建议 &lt;5k，保证内存与毫秒级  
- 启动时建索引；支持 `reload()`（配置热更）  
- **与 `@chatvein/vector` / 记忆 FTS 分轨**：本索引只活在 routing 模块内存里，不写 PGlite

### 6.3 检索与投票

```
hits = bm25.search(query, { limit: 5 })
若 hits[0].score < SCORE_MIN → 不采用 BM25（保持规则结果 / unknown）

对 hits：
  weight_i = score_i（或 softmax）
  band*   = argmax_band Σ weight
  tools*  = 投票；档为 none | unknown | full（unknown = 待 L2）

若 band* 票权占比 < VOTE_RATIO（如 0.6）→ 不自信，仅 bump score，不 override band
否则：
  与规则结果融合：
    - 规则已有 override.band → BM25 只作 reasons 附加
    - tools 经 synthesizeTools 与规则侧合并（negate 锁定 none；unknown 粘性，不可被 BM25 冲掉）
    - 否则采用 band* / 合成后的 tools*，confident = (topScore 高且占比够)
```

中文：入库与查询前用同一套轻量分词（空格/`segment` 简易切或按字 bigram）；**不要**为此强上 nodejieba，除非评测证明必要。

### 6.4 依赖选型

| 依赖 | 用途 | 说明 |
|------|------|------|
| **`wink-bm25-text-search`** | 路由先例内存 BM25 | 与 [`04-依赖选型`](../phase1/04-依赖选型.md) P1 候选对齐；**路由先用、记忆后用可共用包** |
| 备选 MiniSearch | 倒排 + BM25 类打分 | 若 wink API 不贴再评 |

否决：每轮对 PGlite 全表 FTS 做路由（延迟与耦合记忆）；用 embedding Semantic Router 冒充 L1（成本与「无 AI」红线不符）。

## 7 Score → Policy 映射

规则 `bump` 累加得到 `score`（建议初始 0，可夹紧到 0..100）。

| band | score（无硬 override 时） | modelTier | tools | maxSteps | memoryRecall |
|------|---------------------------|-----------|-------|----------|--------------|
| trivial | 仅硬规则 | weak | none | 0 | false |
| simple | 0–25 | weak 或 medium | none 或 unknown | 1–2 | 可选 |
| standard | 26–55 | medium | full† 或 unknown | 默认（如 8） | true |
| complex | ≥56 | strong | full† | 更高（如 16） | true（可 `allowSubAgents`） |
| unknown | 灰区 / 低置信 | **medium** | unknown 或 full† | 默认 | true |


† 仍受 `role.tools` 白名单裁剪（[01 §4.3](./01-核心骨架.md)）。

**保守默认（`confident=false`）**：`standard` 策略或上表 unknown 行；**禁止**默认 trivial。

策略副作用分流：

| 字段 | 谁消费 | 可否自动执行 |
|------|--------|----------------|
| `allowSubAgents` | `@chatvein/agents` | 可以（在预算内创建子 Agent） |
| `hintUserCreateGroup` | **仅 app UI** | **否**；用户确认后走 `group:*` IPC |
| `hintUserForge` | **仅 app UI** | **否**；用户确认后派 Forge |

## 8 模块结构与 API

建议落在 `packages/chatvein/agents/src/routing/`（实现稳定后再评估是否抽包）：

```
routing/
  pipeline.ts            # L1 → L2 编排；对外 HeuristicRouter
  index.ts
  l1/                    # 启发式：features / rules / bm25 / materialize
  l2/                    # 弱模型分类 stub（Passthrough）
  l3/                    # 预留
  locales/               # 语言资源（一期仅 zh）
    _common.json
    zh.json
    prototypes/zh.json
  __tests__/
```

```ts
export interface HeuristicRouterOptions {
  rules: object[]                    // json-rules-engine rules
  prototypes: RoutePrototype[]
  scoreTable?: ScoreTable
  bm25?: { scoreMin: number; limit: number; voteRatio: number }
  enabled?: boolean                  // false 时恒返回 conservative standard
}

export class HeuristicRouter {
  constructor(options: HeuristicRouterOptions)
  route(input: {
    text: string
    session: Pick<HeuristicCtx,
      'turnIndex' | 'lastBand' | 'lastAssistantHadTools' |
      'recentFailure' | 'activeMode' | 'forceTier'>
  }): RouteDecision                  // 同步或 async（engine.run 为 Promise）
  reloadRules(rules: object[]): void
  reloadPrototypes(p: RoutePrototype[]): void
}
```

Cordis：可选 `ctx.agents.router` 或在 `Agent.handle` 内组合；**路由逻辑不进 app**。

## 10 测试与金标

| 类型 | 要求 |
|------|------|
| 单测 features | 寒暄误伤、「你好+长任务」不得 trivial |
| 单测 rules | 每条 P0 规则至少 1 正 1 反 |
| 单测 bm25 | 低分不采用；票权不足不 override |
| **金标集** | ≥50 条 `{ text, expectBand, expectTools? }`，CI 断言；改词典/规则必须跑 |

假阳性门禁：标注为 `complex`/`standard` 且需工具的样本，**不得**被判成 `tools:none` 的 trivial/simple。

## 13 否决与边界

| 方案 | 结论 |
|------|------|
| 仅 LLM 分类每条消息 | 否：贵、慢、简单句浪费；作 L2 即可 |
| Semantic Router（embedding）作 L1 | 否：违背无 AI/毫秒红线；可作未来 L1.5+ |
| BM25 查全量记忆当复杂度 | 否：相关≠复杂；与 recall 耦合 |
| nlp.js 意图模型作 L1 | 否：训练/维护成本高，定位偏 L2 |
| Agent / 路由自动拉群、自动建群、自动「升级成群」 | **永久否决**：拉群是用户客户端操作；最多 `hintUserCreateGroup` |
| 用「拉群」表达 Agent 多智能体 | **否**：Agent 自发形态一律称**子 Agent**（`allowSubAgents`） |
| 自动派 Forge | 否（一期）：只 `hintUserForge`，用户确认 |
| 规则里写复杂 NLP | 否：前移到 `extractFacts`，规则只读布尔/数值 |

开放问题（实现前可再钉）：

1. trivial 是否完全本地模板、不调 weak LLM（体验 vs 成本）  
2. 追问继承：`lastBand` 衰减系数（建议 0.5）是否写入 scoreTable 配置  
3. 路由是否独立成 `@chatvein/routing`（建议 R2 后再拆，避免包膨胀）  
4. `allowSubAgents` 默认上限（子 Agent 个数 / 总步数）与 BudgetGuard 如何共用

## 14 与 Forge `TaskComplexity` 的关系

Forge 编译任务已有 `estimatedComplexity: low|mid|high`（[`common/task`](../../packages/chatvein/common/src/task.ts)）。Chat 路由的 `ComplexityBand` 是**面向自然语言入口**的并行概念：

| Chat band | Forge complexity | 模型档直觉 |
|-----------|------------------|------------|
| trivial / simple | low | weak |
| standard | mid | medium |
| complex | high | strong |

不强制同一枚举，避免 compiler 与 chat 耦合；文档层保持映射即可。
