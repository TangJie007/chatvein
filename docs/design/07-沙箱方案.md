## 1 决策摘要

| 项 | 内容 |
|----|------|
| **选定（P0 / 默认）** | **独立工作区 + 受限 `child_process`（`LocalSandboxProvider`）** |
| Windows | ✅ 原生支持 |
| 内嵌程度 | **完全内嵌，零外部依赖**（无需 Docker Desktop / 云账号） |
| 能力包 | `@chatvein/sandbox`（Cordis 插件 → `ctx.sandbox`） |
| 执行器 | Node 内置 `child_process`（一期不引入 `execa`，除非封装成本过高再加） |

---

## 2 为什么选它

Forge 是 **Coding Agent**：要跑真项目的 `npm/pnpm`、`build`、`test`、`git`、文件 patch。因此：

| 候选 | 结论 |
|------|------|
| **独立工作区 + 受限 child_process** | **采用**：可跑真工程、Windows 最好、桌面可分发 |
| Docker 默认 | 否：用户需装 Docker，非「完全内嵌」→ **P1 可选** |
| V8 isolate（isolated-vm / Secure Exec） | 否：不适合整仓 build/test，仅适合「跑一段 JS」 |
| 云沙箱（E2B 等） | 否：非内嵌；第二期再议 |

三层隔离中的定位：

1. **L1 sidecar**：崩溃隔离（进程）  
2. **L2 local sandbox（本决策）**：工作区 + 命令隔离（**内嵌默认**）  
3. **L3 Docker**：对齐赛事（P1）

---

## 3 P0 强制约束

1. **工作区**：`runs/<run_id>/workspace/`，从模板拷贝；工具读写不得越出该根（路径规范化 + 越界拒绝）。
2. **cwd**：所有 `exec` 的 `cwd` 锁定为 workspace（或显式子目录且仍在根内）。
3. **env 白名单**：不继承宿主敏感变量（API Key 等只留在 harness 进程）；沙箱仅注入构建所需变量（如 `PATH`、`NODE_ENV`、npm registry）。
4. **命令白名单**：仅允许配置的 npm/pnpm/node/git/lint/构建/测试等；其余拒绝并写 trace。
5. **超时**：按工具类型限制（与 PRD 工具表一致）；超时杀进程树。
6. **输出截断**：stdout/stderr 进上下文前经 `@chatvein/context` 截断器。
7. **环境快照**：Node/OS/核心依赖版本写入 `run.json`。
8. **调用边界**：`tools` / `verifier` 只经 `SandboxProvider.exec`，禁止直接 `spawn` 宿主路径。

## 4 接口草案

```ts
export type SandboxProviderKind = 'local' | 'docker' // docker = P1，默认 local

export interface ExecInput {
  argv: string[]           // 已解析 argv，禁止 raw shell 字符串随意拼接
  cwd?: string             // 相对 workspace；越界拒绝
  env?: Record<string, string>
  timeoutMs: number
}

export interface ExecResult {
  code: number | null
  signal: string | null
  stdout: string
  stderr: string
  truncated: boolean
  durationMs: number
}

export interface SandboxProvider {
  readonly kind: SandboxProviderKind
  prepare(runId: string): Promise<{ workspacePath: string }>
  exec(input: ExecInput): Promise<ExecResult>
  snapshot(): Promise<{ node: string; os: string; deps?: Record<string, string> }>
}
```

配置（`forge.config`）：

```ts
sandbox: {
  provider: 'local',           // 锁定默认；P1 可改 'docker'
  workspaceTemplate?: string,  // 模板项目路径
  allowCommands: string[],     // 命令白名单
  envAllowlist: string[],
  network: { npmRegistry?: string }
}
```

## 6 验收（M1-5）

1. 两次 run 的 workspace 路径互不覆盖；删除一个不影响另一个。  
2. 越界路径 / 白名单外命令 → 拒绝，且有 trace。  
3. 宿主 `process.env` 中的假 API Key 不出现在沙箱子进程 env。  
4. 超时命令被杀掉，返回结构化 `ExecResult`。  
5. `pnpm`/`node` 在 workspace 内能跑通最小 fixture 的 install + test。  
6. 纯 Node（sidecar）可跑，无 electron / Docker 依赖。
