# 决策笔记：赛事需求从对话框进入（不绑定项目仓）

状态：已落地

## 背景

赛事两轮输入不同：第一轮在对话框直接描述需求；第二轮在对话框上传需求文档并加说明。需求文档**不在**参赛项目仓库内。原 Forge 入口把用户话写成 `# 用户需求` 丢进会话 memory，易被模型当成「需求管理」业务域，且无法挂上传文档。

## 决策

1. **双入口合成同一份会话侧需求 MD**（`workspace/memory/requirement-*.md`）：仅对话 / 仅上传 / 上传+说明；**不写入** `devProjectRoot`。
2. `ChatSendInput.attachments` + 消息表 `attachments_json`；编程档 Composer 回形针选 `.md/.txt`。
3. 合成文案标题改为「编码任务说明」，并写明「非项目仓文件」与执行约束，降低域歧义。
4. Forge 内核仍要求 `requirementPath`；变更只在 Chat→Forge 边界。

## 备选方案

**把需求文件拷进项目根**：污染参赛仓、与「需求不在项目里」冲突。

**Forge 直接读上传绝对路径**：会话外文件生命周期难管；统一落到 memory 便于续跑与审计。

**办公 ReAct 读文档再 delegate**：正确长期形态，但本轮先打通赛事双入口最小闭环。

## 影响

- 收益：对齐赛事两轮；上传+说明可空正文。
- 代价：附件路径依赖本机文件仍在；重试依赖落库 `attachments`。
- 注意：项目根仍要选（改代码的 jail）；需求与代码分处两端。
