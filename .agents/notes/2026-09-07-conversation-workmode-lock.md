# 决策笔记：单会话工作模式锁定

状态：已落地

## 背景

对话页有三档工作模式（日常办公 / 编程开发 / 个性化 Agent），原先存在全局 `localStorage` 偏好，可随时切换。同一会话内混用办公 ReAct 与 Forge 编排，会导致上下文、工具面与产物语义错乱。产品要求：**单对话一旦开聊，模式不可再改**；换模式请新建对话。

## 决策

- `Conversation.workMode` 持久化到 SQLite（`conversations.work_mode`）；空会话未锁定。
- 首条有效 `send` / `retry` 时 `ChatService.lockWorkMode` 写入并锁定；之后请求模式不一致则拒绝。
- UI：有 `workMode` 或已有消息时禁用其它档位；选中会话时同步展示锁定模式。
- 空会话仍可读本地偏好切换；新建对话不继承上一会话的锁定，只继承偏好默认值。

## 备选方案

### 为什么不用「仅 UI 禁用、服务端不校验」？

IPC 仍可绕过；模式是执行引擎选择，必须服务端强制。

### 为什么不用「全局模式、会话不存」？

切换会话时无法恢复该会话当时用的引擎；也无法阻止「先编程再切办公继续聊」。

### 为什么不在创建会话时就锁定？

用户常先建空会话再选档；锁定点定在「首条聊天」更符合「只要有聊天就不能切换」。

## 影响

- 旧会话无 `work_mode`：有消息时 UI 先按消息数锁定当前偏好，下次 send 才落库。
- 换模式成本变为「新建对话」；同一会话内不能中途改引擎。
