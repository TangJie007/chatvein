# 决策笔记：对话不落盘（移除 conversations.json）

状态：已落地

## 背景

会话曾写入 `{userData}/forge/conversations.json`，重启后仍能看到历史。用户明确要移除该落盘：正式「记忆」尚未设计，聊天记录持久化会与记忆能力混淆，且当前不需要跨启动保留对话。

## 决策

- `ChatStore` 改为**仅主进程内存**：`load`/`save` 只读写内存对象。
- 首次 `load` 时尝试删除遗留的 `conversations.json`（及 `.tmp`）。
- 当前进程内仍可多轮对话（`send` 仍拼 history）；**重启后会话列表为空**。

## 备选方案

**继续 JSON 落盘当聊天历史**：与「记忆待重设计」纠缠，用户否决。

**立刻上 @chatvein/memory**：方案未定，不做。

## 影响

- 收益：无跨启动聊天残留；记忆可单独设计。
- 代价：刷新/重启丢失会话；用户需知悉。
- 后续注意：若仅要「聊天历史」而非 Agent 记忆，应另开明确的 history 存储，勿复用记忆包语义。
